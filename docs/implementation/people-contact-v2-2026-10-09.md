# BOB: ค้นหาคนและข้อมูลติดต่อ — 9 ตุลาคม 2026

## ขอบเขตที่ยืนยัน

- ใช้ Org/Sub Org เป็นสังกัดหลัก; Group/Corporate Department/Function-Team เป็นอีกมิติหนึ่ง ใช้เมื่อผู้ใช้ระบุหรือเพื่อขยายความ ไม่รวมสมาชิกข้ามมิติ
- Supervisor 1 เป็นหัวหน้าโดยตรง; Supervisor 2 เป็นหัวหน้าที่ดูแลภาพรวม ไม่ถือว่าเป็นผู้อนุมัติทุกเรื่อง
- ยังไม่มีทะเบียนความรับผิดชอบรวม จึงไม่อนุมานเจ้าของงานหรือความเชี่ยวชาญจากตำแหน่ง/แผนก
- คง Model หลักในการตอบผู้ใช้ รุ่นทดลองยังไม่เปลี่ยนมารับคำถามจริง

## การเปลี่ยนแปลง

1. ค้นชื่อร่วมกับสังกัด เช่นชื่อซ้ำใน IT กับทีมอื่น ถ้าไม่ชัดให้เลือกจากชื่อเต็มและ Org/Sub Org
2. แยกคำถามหลายเป้าหมายได้ไม่เกิน 4 รายการ ตอบส่วนที่ค้นพบและบอกส่วนที่ยังไม่พบ
3. รองรับหลายฟิลด์ เช่นชื่ออังกฤษ อีเมล ตำแหน่ง และสังกัด; คำถามขอจำนวนพร้อมอีเมลแสดงรายชื่อด้วย
4. จำบริบทการค้นแยกผู้ถามและบทสนทนา 30 นาที: จำนวน → รายชื่อ → อีเมล, เลือกคน, กรอง และดูหน้าถัดไป ครั้งละไม่เกิน 20 คนในทีมที่ระบุ
5. อ่านทะเบียนใหม่ทุกครั้งที่ใช้บริบท ไม่เก็บคำตอบที่ Model เคยเดาเป็นข้อเท็จจริง; เปลี่ยนเรื่องหรือ /clear ล้างบริบท
6. เพิ่มรายชื่อ Org/Sub Org และแยก Supervisor 1/2 จาก Excel
7. คำถามผู้รับผิดชอบใช้ข้อความติดต่อที่ระบุชัดใน KB พร้อมแหล่งอ้างอิง หรือทะเบียนที่ยืนยันแล้ว หากไม่มีให้บอกช่องว่าง
8. แยกอีเมลสมาชิกจากอีเมลกลาง ขอ email ของ HR หมายถึงสมาชิก เว้นแต่ผู้ใช้ระบุอีเมลกลาง
9. คำถามช่องทางติดต่อเรื่องเงินเดือน/วันลาแบบเฉพาะเจาะจงผ่านได้ ข้อมูลส่วนบุคคลหรือคำถามผสมข้อมูลต้องห้ามยังถูกปฏิเสธ
10. Prompt ใหม่ `people-intent-v2` มี fallback ในโครงการ แยกจาก prompt เดิมเพื่อให้ย้อนรุ่นได้

## ทะเบียนช่องทางติดต่อที่ต้องเติม

ไฟล์ `src/people/contact/registry.json` เริ่มเป็น array ว่าง ไม่ได้ใส่ชื่อผู้รับผิดชอบที่คาดเดา

แต่ละรายการต้องมี:

| ฟิลด์ | ความหมาย |
|---|---|
| topic / aliases | เรื่องที่ติดต่อและชื่อเรียกอื่นที่ยืนยัน |
| sourceUrl | ลิงก์ HTTPS ของเอกสารอ้างอิง |
| quote | ข้อความจากแหล่งข้อมูลที่ระบุช่องทางติดต่อ |
| team หรือ personEmail | ทีมที่ยืนยัน หรืออีเมลบุคคลที่ยังอยู่ในทะเบียน |
| sharedEmail | อีเมลกลาง เฉพาะเมื่อมีหลักฐานยืนยัน |
| verifiedAt | วันที่ตรวจยืนยันแบบ ISO |

ระบบใช้รายการที่ยืนยันภายใน 180 วันตามค่า freshness ที่มีอยู่ ค่านี้เป็นค่าเทคนิคสำหรับทบทวนข้อมูล ไม่ใช่กติกา HR ที่ประกาศใหม่ หลังแก้ registry ต้องทดสอบและ deploy เช่นเดียวกับ code

ฝ่าย HR/IT/Product ควรเติม “เรื่องที่รับผิดชอบ → ช่องทางแรก → ช่องทางยกระดับ → เงื่อนไข/ขอบเขต → แหล่งอ้างอิง → วันที่ยืนยัน” โดยแยกผู้ติดต่อ ผู้ดูแลภาพรวม และผู้มีสิทธิ์อนุมัติ ใช้ชื่อทีมจริงตามทะเบียน ไม่มีการกำหนดเจ้าของงานหรือเส้นตายใหม่ในงานนี้
